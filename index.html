About

Somewhere between a quiet desk and a room full of ideas is where I work best.

Software, to me, is more than code on a screen. It begins with understanding a problem, asking thoughtful questions, and slowly turning something uncertain into a system people can actually use.

That curiosity has taken me across frontend interfaces, backend services, APIs, databases, payment workflows, and production deployments. More recently, it has meant contributing to payment portal functionality at MoneyGram, developing a full-stack commercial services platform with React, TypeScript, Supabase, PostgreSQL, and Stripe, and creating internal productivity tools using Python, Vue.js, PostgreSQL, and REST APIs.

But building the feature is only part of the work.

The details surrounding it matter just as much: understanding why it is needed, clarifying what is unclear, communicating across teams, testing complete workflows, tracing difficult bugs, and making sure the final result feels reliable—not only to the developer who built it, but to the person using it.

My approach is calm, practical, and ownership-driven. There is no need to be the loudest person in the room when thoughtful questions, dependable execution, and consistent work can speak over time.

Outside of code, public speaking, technical events, travel, and new experiences keep me curious. They introduce different perspectives, sharpen observation, and often change the way I think about people, products, and problems.

The goal is not simply to become someone who builds software.

It is to become someone who understands what should be built, brings people and ideas together, and helps meaningful products travel the full distance—from an early thought to a real outcome.

Projects

ChopURL

Short links, thoughtfully engineered.

ChopURL is a full-stack tool for turning long, awkward URLs into clean, shareable links. Anyone can shorten a URL, while signed-in users get a private dashboard to create custom aliases, monitor clicks, and manage their links.

What began as a simple URL shortener became an exploration of real backend challenges: preventing duplicate aliases, preserving click counts during simultaneous requests, separating one user’s data from another’s, and automatically expiring old records.

I built the API with FastAPI and Redis, the interface with Vue 3, and authentication with Supabase. The project is deployed using Vercel and Render.

Built with: FastAPI · Redis · Vue 3 · Supabase Auth · Docker

ArchAI

Describe the system. See the architecture.

ArchAI is a full-stack tool that transforms natural-language system requirements into clear, downloadable AWS architecture diagrams. Users describe the application they want to build, and ArchAI identifies the requested services, generates a structured architecture, validates its components and relationships, and renders the result as a professional PNG.

What began as a diagram generator became an exploration of a larger AI engineering challenge: model output can look correct while still omitting services, referencing invalid nodes, exposing internal class names, or producing disconnected architectures. I built a validation and repair pipeline that checks every supported requested service before allowing the diagram to be rendered.

I built the interface with React and TypeScript, the API with FastAPI and Pydantic, and the AI workflow with OpenAI structured output. Diagrams are rendered deterministically using Python Diagrams and Graphviz, while Docker provides a reproducible local setup. ArchAI runs locally and does not provision AWS resources.

Built with: React · TypeScript · FastAPI · Pydantic · OpenAI API · Python Diagrams · Graphviz · Docker
