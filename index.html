About

I do my best work in the space between a quiet question and a working system.

I’m Jyothsna Karuparthi, a software engineer and an optimistic ambivert. I enjoy exchanging ideas with people, but I value quiet focus just as much. I naturally look for a way forward, even when the answer is not immediately clear.

Software, to me, begins before the code. It starts with understanding what is actually broken, asking better questions, and building something people can trust.

My work spans frontend interfaces, backend services, APIs, databases, and payment workflows. At MoneyGram, I contribute to payment portal functionality and troubleshoot backend issues affecting transaction workflows. At Community Dreams Foundation, I helped build a full-stack platform from the ground up while translating stakeholder needs, coordinating across technical and business teams, and helping guide the project toward production.

That experience showed me that one of my strengths lies beyond implementation. I am equally drawn to creating clarity, connecting people and decisions, and helping a product move from an uncertain idea to a real outcome.

I do not need to be the loudest person in the room. Thoughtful questions, honest communication, and dependable execution tend to build trust over time.

Outside of code, public speaking, travel, technical events, and conversations with people from different backgrounds continue to shape how I understand problems, products, and the people they are built for.

My goal is to keep growing as an engineer while earning broader ownership of the products and teams I contribute to.

Projects

ChopURL

A URL shortener, with the actual work hidden underneath. Anyone can shorten a link. Sign in and you get a dashboard: custom aliases, click counts, the ability to see and manage what you've made.

Most of the effort went into making the backend not lie to you. Two people trying to claim the same alias at once. Click counts staying accurate when requests overlap. One user never seeing another user's links. Old links expiring on their own instead of piling up. FastAPI and Redis run the API, Vue 3 is the frontend, Supabase handles auth, and it's deployed across Vercel and Render.

Built with: FastAPI · Redis · Vue 3 · Supabase Auth · Docker

Live app → GitHub →

ArchAI

You describe a system in plain English, ArchAI gives you back the AWS diagram. Say "a web app with a load balancer, two EC2 instances, and an RDS database" and it figures out the services, builds the architecture, checks it, and renders a PNG.

The diagramming part turned out to be the easy part. The real issue is that model output can look convincing while quietly being wrong, dropping a service you asked for, pointing to a node that was never created, leaking an internal class name into what should be a clean label. So there's a validation and repair step that confirms every requested service actually made it in before anything gets rendered. React and TypeScript on the frontend, FastAPI and Pydantic for the API, OpenAI for the structured output, Python Diagrams and Graphviz doing the actual drawing.

Built with: React · TypeScript · FastAPI · Pydantic · OpenAI API · Python Diagrams · Graphviz · Docker

GitHub →

CrowdShield

Content moderation that doesn't choke when traffic spikes. Submissions land in a Redis queue, workers pick them up and send them to OpenAI for scoring, so a burst of incoming content never blocks on an API call.

If OpenAI fails mid-request, retry logic catches it. Every decision gets written to PostgreSQL so there's a record of why something was flagged. Admins watch it happen live through a WebSocket dashboard instead of refreshing a page to check status.

Tools: Spring Boot · Redis · PostgreSQL · OpenAI · WebSockets
